# Persian RAG

A simple Retrieval-Augmented Generation (RAG) application for asking questions about Persian documents.

The application allows users to upload multiple PDF or DOCX documents, search for relevant information, and generate answers in Persian using a local Large Language Model (LLM).

## 2. Requirements

Before installing the application, prepare the following:

- Ubuntu 24.04 LTS or another supported Linux distribution.
- Python 3.12.
- Anaconda or Miniconda.
- Git.
- Internet connection for installing packages and downloading the embedding model.
- Ollama for running Gemma models.
- llama.cpp for running Liquid AI GGUF models.

The application can use local models and does not require a cloud API for its current local configuration.

## 3. Download the Project

Open a terminal and clone the repository:

```bash
git clone https://github.com/alirezaahm/persian_rag.git
```

Enter the project directory:

```bash
cd YOUR_PROJECT_PATH/v11
```

Make sure that the terminal is inside the directory containing `main_v2.py`.

## 4. Install the Python Environment

Two environment files are provided:

- `rag_requirements_conda.yml`
- `rag_requirements_pip.txt`

You can use these files to recreate the Python environment on another computer.

### Method 1: Install using Conda (Recommended)

Create a new environment:

```bash
conda env create -f rag_requirements_conda.yml
```

Activate the environment:

```bash
conda activate py312
```

The environment name depends on the `name:` field inside the YAML file. If it is different from `py312`, use that name instead.

Check the Python version:

```bash
python --version
```

Expected version:

```text
Python 3.12.x
```

If the YAML file already contains a `pip:` section, its pip packages are installed as part of the Conda environment creation.

If some pip packages are missing, you can install them using:

```bash
python -m pip install -r rag_requirements_pip.txt
```

### Method 2: Install using pip

If you do not want to use the Conda environment file, create a new Python environment:

```bash
python3.12 -m venv .venv
```

Activate it:

```bash
source .venv/bin/activate
```

Upgrade pip:

```bash
python -m pip install --upgrade pip
```

Install the required packages:

```bash
python -m pip install -r rag_requirements_pip.txt
```

Check the installed packages:

```bash
python -m pip list
```

**Important:** Use one installation method as your main method. The Conda YAML and pip freeze files may contain overlapping packages. Installing both blindly can create package version conflicts.

## 5. Prepare the Local LLM

The application currently supports two local LLM frameworks.

### Option A: Ollama with Gemma

Install Ollama by following its official installation instructions:

[https://ollama.com/download](https://ollama.com/download)

Download the required Gemma model:

```bash
ollama pull gemma3:1b
```

Or:

```bash
ollama pull gemma3:4b
```

Check the installed models:

```bash
ollama list
```

Make sure the Ollama service is running.

### Option B: llama.cpp with Liquid AI

Install llama.cpp and make sure that `llama-server` is available in the terminal:

```bash
llama-server --version
```

Download the required GGUF model files and place them in an appropriate directory.

The model paths must be updated in `main_v2.py` if they are different from the paths in the project configuration.

For example:

```text
/home/username/AI_Models/LFM3-1.7B-Q4_K_M.gguf
```

The application starts the llama.cpp server when the user asks a question.

## 7. Use the Application

1. Select an LLM framework from the sidebar.
2. Select the desired LLM model.
3. Select an embedding provider and embedding model.
4. Set the number of retrieved chunks.
5. Upload one or more PDF or DOCX documents.
6. Wait until document indexing is complete.
7. Enter your question in Persian.
8. Press the Ask button.
9. Read the generated answer.
10. Open the retrieved document chunks section to inspect the sources.

The application supports multiple documents in one indexing operation.

## 8. How the RAG Pipeline Works

The application has two main stages.

### Stage 1: Document Indexing

```text
PDF / DOCX Documents
        |
        v
Text Extraction
        |
        v
Persian Text Normalization
        |
        v
Text Chunking
        |
        v
Embedding Generation
        |
        v
Vector Normalization
        |
        v
Save Chunks and Embeddings
```

The application extracts text from documents and divides it into smaller sections called chunks.

Each chunk keeps its source document and page information.

The embedding model converts each chunk into a numerical vector.

The vectors and chunk information are saved in the `data/persian_rag_index/` directory.

### Stage 2: Question Answering

```text
User Question
      |
      v
Persian Text Normalization
      |
      v
Question Embedding
      |
      v
Cosine Similarity Search
      |
      v
Retrieve Top-K Chunks
      |
      v
Build LLM Context
      |
      v
LLM Answer Generation
      |
      v
Persian Answer + Sources
```

The application converts the user's question into an embedding vector.

It compares this vector with the stored document vectors and retrieves the most relevant chunks.

The retrieved text is sent to the LLM as context.

The LLM generates an answer based on the retrieved information.

If the retrieved context does not contain the answer, the application instructs the LLM to respond:

```text
پاسخ مناسب یافت نشد.
```

## 9. Document Index Storage

The application stores three main files:

| File                | Description                                    |
| ------------------- | ---------------------------------------------- |
| `chunks.jsonl`      | Stores document text and source metadata.      |
| `embeddings.npy`    | Stores numerical embedding vectors.            |
| `index_config.json` | Stores the embedding provider, model, and URL. |

The index can be loaded again when the application starts, provided the embedding configuration is compatible.

If the embedding model changes, the documents must be indexed again.

## 10. Important Notes

- The current application supports PDF and DOCX documents.
- Multiple documents can be uploaded and indexed together.
- PDF files should contain extractable text. Scanned PDFs may require an OCR feature.
- The embedding model is loaded when it is needed.
- The current local SentenceTransformers embedding model runs on the CPU.
- The number of retrieved chunks can be changed from the sidebar.
- The Reset button deletes the saved document index.
- The Exit / Turn Off button releases application resources and stops the application.
- Model file paths must be updated when using another computer.
- API credentials must never be committed to Git.
